# 스타일 가이드

write-post 스킬 2단계(초안)와 3단계(교정)에서 읽는다.

## 문체

- 존댓말만. 해요체(~해요, ~예요, ~죠)와 합니다체(~합니다, ~입니다) 둘 다 허용.
- 권장: 해요체 위주에 합니다체를 섞기. 최신 글("ECharts → uPlot → SciChart")이 이 방식이다.
- 한 문단 안에서 같은 종결 어미가 4문장 넘게 이어지지 않게 섞는다.
- 반말 금지. 예외: 짧은 강조 문장("이번이 진짜 마지막입니다(아마도)" 같은 혼잣말), 직접 인용, 코드 주석.
- 기존 합니다체 글을 고칠 때는 그 글의 문체를 유지한다. 문체를 바꾸려면 사용자에게 먼저 묻는다.

## 표기

- 영어 용어는 첫 등장에만 괄호로 병기하고 이후는 한글만. 업계에서 영어 그대로 쓰는 약어(API, FDC, LTTB 등)는 첫 등장에 풀이만 붙인다.
- 굵은 글씨는 글 전체에서 몇 번만. 문장마다 핵심어를 굵게 하지 않는다.
- 숫자는 단위와 같이, 출처가 업체 자료면 본문에 "업체 자료"라고 밝힌다.
- 링크 텍스트는 대상이 무엇인지 알 수 있게 쓴다("여기" 금지).

## AI 티 점검표

한국 독자가 "AI가 쓴 글"로 느끼는 신호. 3단계에서 훑고, 강한 신호는 0개를 목표로 한다.

### 강한 신호 (반드시 고침)
- 모든 H2가 같은 형태("1. ~다", "~하는 법")이고, 섹션마다 같은 틀(설명 → 콜아웃 → "화면에서는…") 반복
- 본문을 다 쓴 뒤 같은 내용을 정리 표로 한 번 더 요약
- "- **라벨:** 설명" 형태 불릿이 이어짐, 굵은 글씨 남발
- 대구형 짧은 명언 반복: "A가 아니라 B였습니다", "그럴듯해 보여도 ~할 수 없습니다", "보기 좋지만 ~에는 쓸 수 없습니다"
- 메타 도입 "이 글은 ~를 정리한 것입니다", 교훈형 마무리 "~해 보시길 권합니다"
- 지어낸 경험이나 출처 없는 수치

### 중간 신호 (줄임)
- 한글(영어) 병기 반복
- 독자가 아니라 작성자를 위한 문장 (예: 보안 확인용 "특허에도 공개된 방식입니다" 반복)
- 종결 어미가 전부 같고 문장 길이가 고름. 짧은 문장과 긴 문장을 섞는다.
- 상투 평가어: "생각보다 ~합니다", "충분히 전달됩니다", "~하는 게 좋습니다" 반복
- 콜아웃 3개 이상

### 약한 신호 (많을 때만)
- 문두 "그래서/또한/따라서" 반복
- "~할 수 있습니다" 반복 (단언할 수 있으면 단언)

### 대체 방법
- 경구 대신 구체 사례·수치로 말한다.
- 정리 표 대신 마지막 문단에서 한두 문장으로 닫는다.
- 라벨 불릿은 문장으로 풀어 문단에 녹인다.
- 경험이 필요한 자리에 경험이 없으면 TODO를 남기고 사용자에게 묻는다. 대신 쓰지 않는다.

## 민감 정보

- 회사명, 고객명, 프로젝트명, 내부 화면·시스템 이름, 내부 약어, 티켓 번호 금지.
- 업무 경험은 일반화해서 쓴다 ("제조 설비 데이터 대시보드").
- 화면 아이디어가 회사 제품 기능과 겹치면, 공개 자료(특허·논문·제품 문서)로 확인된 일반 개념까지만 쓴다. 기본값, 수치 설정, 화면 배치, 출시 시점은 쓰지 않는다.
